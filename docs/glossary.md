# Glossary

One short definition per term used on this site, with how it is known and the page that explains
it. Where the community knowledge base naya-create-kb uses a term differently, the entry says so; its
coined terms are collected at the end with our translation, so that readers of both sites can move
between them.

!!! note "Conventions"
    Byte strings are lower-case hex in code spans; a **params** or **reply string** starts at frame
    byte 8 (see [Transport](protocol/transport.md)). Command ids are written `category/subcommand`, for
    example `30/1004`. Versions are written 3.41.0 (keyboard) and 2.3.3 (module); the keyboard reports
    them with a leading zero on the wire (see [Firmware versions](firmware/versions.md)).

| **Active profile** | The NayaFlow profile marked `ON_BOARD`, the only one "Flash Create" writes (UI: "Active profile (flashes to Naya device)"). | <span class="tag static">STATIC</span> <span class="tag doc">DOC</span> | [NayaFlow and NayaCore](software/nayaflow.md) |
| **Batch** (vendor term) | A shipment wave of the Create. Batch 0 = 100 test units (January 2025, tester firmware without remapping or modules); Batch 1 about 150; Batch 2 two waves of 250; Batch 3 two waves of about 500; Batch 4 about 1300; the vendor called Batches 0-2 production-validation units; all pledges had shipped by 2025-09-11. | <span class="tag doc">DOC</span> (Kickstarter updates 18-22 and 25) | [History](software/history.md) |
| **Battery Zero** (vendor term) | The vendor's name for a rare fault that drains a module "beyond recovery"; it announced firmware and hardware fixes and a recovery mode (see Recovery mode; NayaFlow 1.3.8 notes "module recovery support for battery Zero"). | <span class="tag doc">DOC</span> (Kickstarter update 21, 2025-06-16; 1.3.8 notes) | [Power](hardware/power.md) |
| **Bay** (module bay) | The dock on each half where a module sits; the left bay and right bay each light a 24-index block of the LED map (88-111, 112-135). | <span class="tag measured">MEASURED</span> (owner's board, 2026-09-08) | [Module dock](hardware/dock.md) |
| **Bay record** | A keymap record at positions `0x4a`-`0x51` (one per module type and side) whose type byte picks the module-config slot that layer uses; `78` means "inherit from the base layer". | <span class="tag measured">MEASURED</span> (owner's board, 3.41.0, 2026-09-03) | [Keymap](protocol/keymap.md) |
| **Beta channel** | NayaFlow-Beta, a separate app published from `NayaTech/NayaFlow-beta-releases` (16 releases, 2025-09-01 to 2026-07-17); three keyboard firmwares shipped only there (3.39.4, 3.40.0, 3.40.4). | <span class="tag doc">DOC</span> <span class="tag static">STATIC</span> | [History](software/history.md) |
| **Body, wing, dock** | The three hinged parts of a half: the main body, the wing (outer two key columns, tenting hinge) and the dock (thumb keys and module ring). | <span class="tag doc">DOC</span> (Create manual v1.1.x p.9) | [The keyboard half](hardware/half.md) |
| **Boot pass** | The 1-1.7 s every half spends in its bootloader at power-on (USB PID `0x006F` left, `0x00D3` right) before the application starts; distinct from a half **parked** in the bootloader, which stays until an SMP reset. | <span class="tag measured">MEASURED</span> (owner's boards, 2026-09-22) | [Bootloader](firmware/bootloader.md) |
| **Buffer cell** (internal battery) | The small cell in each half that keeps it running while a module is swapped; not meant to power normal use. | <span class="tag doc">DOC</span> (manual p.4; FCC exhibits) | [Power](hardware/power.md) |
| **Byte 3** (chunk countdown) | Frame byte 3 counts the frames still to come: in a chunked write (`02 01 00`) and in a multi-part read reply (`03 02 01 00` for a four-chunk layer); `00` on a single frame, on write acks and on every read request. | <span class="tag measured">MEASURED</span> (our captures of 2026-09-01, 09-03 and 09-17); also reported by naya-create-kb | [Transport](protocol/transport.md) |
| **Category** | Frame byte 4, the command family: `30` REMAP, `be` Bluetooth, `ca` charger, `de` module, `ed` LED, `ee` reset, `f1` firmware, `fa` SPI flash, `fe` system, `ff` host-side meta. | <span class="tag static">STATIC</span> <span class="tag measured">MEASURED</span> (nayactl; NayaCore) | [Command map](protocol/commands.md) |
| **Central / peripheral** | The left half is the central: it owns every REMAP store, drives both halves' LEDs and reaches the right half as `dst 0x51` for the reads it relays (see Proxy); the right half is the peripheral. naya-create-kb calls the left the "merge host". | <span class="tag measured">MEASURED</span> <span class="tag inferred">INFERRED</span> (owner's board, 3.41.0) | [Split link](connectivity/split-link.md) |
| **Continue flag** | The request flags byte `01`, asking for the next chunk of a chunked read; `00` starts (or restarts) the read. | <span class="tag measured">MEASURED</span> (owner's board, 3.41.0) | [Python recipes](tools/recipes-python.md) |
| **CRL / CRR / DG** | The FCC IDs `2BQ4V0825CRL` (left half), `2BQ4V0825CRR` (right half), `2BQ4V0825DG` (dongle); grantee code `2BQ4V`. | <span class="tag doc">DOC</span> (FCC filings) | [Regulatory records](hardware/regulatory.md) |
| **Crown, Gesturepad** (vendor terms) | The Tune's outer rotating ring and its inner touch surface. | <span class="tag doc">DOC</span> (Tune manual v1.1.x p.6) | [Tune](hardware/tune.md) |
| **Danger Zone** | NayaFlow's section with destructive buttons: force module update, Test and Format SPI-Flash (ZMQ event `repair_flash`), Clear all keymap data (`clear_data`), Clear BLE Devices (`clear_ble_devices`). NayaCore dispatches `clear_data` to its ClearAllData operation, which sends `30/10ca`; `clear_all_data` is that operation's process name, not an event. | <span class="tag static">STATIC</span> <span class="tag doc">DOC</span> | [NayaFlow and NayaCore](software/nayaflow.md) |
| **Destination** (`dst`) | Frame byte 2 of a request: `0x50` the left half, `0x51` the right half (on the right half's own port, or through the left half's port for the reads the left relays; see Proxy). | <span class="tag measured">MEASURED</span> (owner's board; create-legacy-firmware[^nh-hw]) | [Transport](protocol/transport.md) |
| **Dock-bus address** | The byte a docked module answers with (`de/1001`, `de/1007`): bit 0 is the side, the high nibble the type (`0x10` Touch, `0x20` Track, `0x40` Tune; `0xF0`/`0xF1` not booted). | <span class="tag measured">MEASURED</span> (owner's board; nayactl pull request #2) | [Modules](protocol/modules.md) |
| **ED** | The LED command category (`0xed`), for live effects and three persistent settings (`ed/1012` scan mode, `ed/1013` maximum brightness, `ed/1014` LED action override). | <span class="tag static">STATIC</span> <span class="tag measured">MEASURED</span> (owner's board, 2026-09-13/16) | [LEDs](protocol/led.md) |
| **EOT** | The `04` byte that ends every frame. | <span class="tag static">STATIC</span> | [Transport](protocol/transport.md) |
| **Flags byte / status byte** | Frame byte 8, and the first byte of every params or reply string on this site. In a request `00` (or `01` = continue); in a reply the status: `00` last, `01` more, `11` not implemented, `16` nothing stored, `18` nothing stored (continuation), `ea` value refused. | <span class="tag measured">MEASURED</span> (owner's boards, 3.41.0 and 3.28.7) | [Transport](protocol/transport.md) |
| **Flash generation A / B** | Two keyboard hardware variants (flash parts) that need different images; B images carry `_64` in their names (`kb_fwl_64.bin`); NayaCore tells them apart by USB PID bit `0x1000`. | <span class="tag static">STATIC</span> | [Firmware images](firmware/images.md) |
| **Flavor** (interrupt flavor) | The hold-tap decision rule stored in every hold-tap record (ZMK's balanced, tap-preferred, hold-preferred, tap-unless-interrupted); valid values 0-3 (4 stops every key); `02` = tap-preferred measured; which of 0, 1, 3 is which is <span class="tag open">OPEN</span>. | <span class="tag measured">MEASURED</span> <span class="tag static">STATIC</span> (owner's board, 3.41.0, 2026-09-03/17) | [Settings and timing](protocol/settings.md) |
| **flow-bg-server** | NayaFlow's Go background server (HTTP API, database, ZMQ bridge). | <span class="tag static">STATIC</span> | [NayaFlow and NayaCore](software/nayaflow.md) |
| **Force update** (module) | NayaFlow's forced module-firmware update for a module that does not answer. | <span class="tag doc">DOC</span> | [Module firmware](firmware/modules.md) |
| **Frame** | One message on the USB serial link: `aa`, three header bytes, category, size, subcommand (2 bytes), flags, payload, XOR checksum, `04`. | <span class="tag static">STATIC</span> <span class="tag measured">MEASURED</span> | [Transport](protocol/transport.md) |
| **Hold-tap** | A key record with a tap action and a hold action (record types `03` and `10`); its body carries the hold kind, tap kind, flavor and tapping term. | <span class="tag measured">MEASURED</span> (owner's board, 3.41.0) | [Keymap](protocol/keymap.md) |
| **Hollow port** | A half whose own USB port opens, completes the handshake and then answers every command with an empty payload while the half still types; seen on the right half while the halves ran different firmware (left 3.41.0, right 3.35.4), and it ends when they match. | <span class="tag measured">MEASURED</span> (create-legacy-firmware[^nh-hw]) | [Transport](protocol/transport.md) |
| **HWID** | NayaCore's id for a half, equal to the half's USB serial string and to the `fe/1004` reply. | <span class="tag static">STATIC</span> <span class="tag measured">MEASURED</span> | [NayaFlow and NayaCore](software/nayaflow.md) |
| **KEYHASH** | The SHA-256 of the public signing key stored in each MCUboot image; one value across every stock keyboard image of the 25 stable releases and of the 16 beta releases. | <span class="tag static">STATIC</span> (create-legacy-firmware manifests) | [Firmware images](firmware/images.md) |
| **KK** | A key position byte (`0x00`-`0x49` for the 74 keys); it equals the record's position. | <span class="tag measured">MEASURED</span>; agrees with naya-create-kb | [Layout and positions](hardware/layout.md) |
| **Layer list** | The keyboard's table of layers, one 20-byte entry each `[index][id][animation][10][16-byte UUID]`; names are host-only. Read with `30/1001`, written with `30/1002`; rewriting it byte for byte restores stored lighting on both halves. | <span class="tag measured">MEASURED</span> (owner's board, 3.41.0, 2026-09-03/10) | [Layers](protocol/layers.md) |
| **LED map** | 136 entries per layer `[position][hue u16 LE][saturation]` covering keys, side bars and both module bays; saturation 150 means "no color set". | <span class="tag measured">MEASURED</span> (owner's board, 3.41.0) | [LEDs](protocol/led.md) |
| **LEN / size** | In a record, LEN is the parameter length (record = LEN + 3 bytes); in a frame, the size byte counts subcommand, flags and payload (payload + 3). | <span class="tag measured">MEASURED</span> | [Transport](protocol/transport.md) |
| **M_Firmware / FlashMemory.bin** | The left half's store for module firmware and the 1 MiB LittleFS bundle NayaFlow uploads into it (SMP image id 4). | <span class="tag static">STATIC</span> | [Module firmware](firmware/modules.md) |
| **MCUboot** | The bootloader on each half (serial recovery over USB CDC, SMP protocol); it only accepts images signed with Naya's key. | <span class="tag static">STATIC</span> <span class="tag measured">MEASURED</span> | [Bootloader](firmware/bootloader.md) |
| **Module-config slot** | An entry of the keyboard's module-config store (`30/1009` list, `30/100b`/`30/100c` data); slot 0 is a blank template; layers pick slots through bay records. | <span class="tag measured">MEASURED</span> (owner's board, 3.41.0, 2026-09-02/03) | [Modules](protocol/modules.md) |
| **Motion category** | The first u32 of a two-word `0f` record in a module field: 0 pointer X, 1 pointer Y, 3 buttons, 4 vertical scroll, 6 horizontal scroll, 8 zoom. | <span class="tag measured">MEASURED</span> <span class="tag static">STATIC</span> | [Module fields](protocol/module-fields.md) |
| **NayaCore** | NayaFlow's C++/Qt service that does all device I/O. | <span class="tag static">STATIC</span> | [NayaFlow and NayaCore](software/nayaflow.md) |
| **NayaFlow** | Naya's desktop configurator (Electron). | <span class="tag doc">DOC</span> | [NayaFlow and NayaCore](software/nayaflow.md) |
| **OneKey** | OpenFlow's name for up to four behaviors on one key (tap, hold, double tap, tap + hold). | <span class="tag doc">DOC</span> (OpenFlow) | [Tools](tools/index.md) |
| **Params / reply string** | This site's way of writing a frame's contents: every byte after the two subcommand bytes up to the checksum, starting with frame byte 8 (the flags byte in a request, the status byte in a reply). `fe/1002` reply `00 00 03 29 00` = status `00`, then the version bytes. | <span class="tag doc">DOC</span> (this site's convention) | [Transport](protocol/transport.md) |
| **Parked** | A half sitting in its bootloader (no lights, no typing) until an SMP `os reset` sent to the port that answers SMP, or a power cycle; recoverable. | <span class="tag measured">MEASURED</span> (owner's board, 2026-09-08 to 09-20) | [Recovery](recovery.md) |
| **Position** | The index of a record in a layer: `0x00`-`0x49` keys, `0x4a`-`0x51` bays, `0x52` and up the second bank. | <span class="tag measured">MEASURED</span> | [Keymap](protocol/keymap.md) |
| **ProtocolCDC / SystemCDC** | NayaCore's names for the binary protocol channel (the one this site documents) and the retired text channel (answered only by firmware older than 3.31.1). | <span class="tag static">STATIC</span> <span class="tag doc">DOC</span> (1.17.2 notes) | [History](software/history.md) |
| **Record** | One entry of a layer, `[position][type][len][param...]`. naya-create-kb calls it a T-record. | <span class="tag measured">MEASURED</span> | [Keymap](protocol/keymap.md) |
| **Recovery mode** (module) | The MODULE_FORCE_CHARGING key (record type `06`, id 401), which force-charges a critically drained module in that half's bay; the module is unusable meanwhile and the mode ends by itself or on restart. | <span class="tag measured">MEASURED</span> <span class="tag doc">DOC</span> | [Disassembly](software/disassembly.md) |
| **REMAP** | Category `0x30`: layer list, layer data, LED maps, module configs, clear-all (`30/10ca`). | <span class="tag static">STATIC</span> <span class="tag measured">MEASURED</span> | [Command map](protocol/commands.md) |
| **Resource** | A stock firmware file as shipped: the whole 663 552-byte slot (header, encrypted image, TLVs, padding and a pre-written swap trailer). | <span class="tag static">STATIC</span> | [Firmware images](firmware/images.md) |
| **Second bank** | Positions `KK + 0x52`, where double tap and tap + hold live for key KK. naya-create-kb calls it the shadow slot and describes "mini" and "full" shadow forms; on the wire both banks carry full 27-byte type-`10` records, and the 10-byte "mini" form matches NayaCore's log re-encoding. | <span class="tag measured">MEASURED</span> (USB capture, 2026-09-03) | [Keymap](protocol/keymap.md) |
| **SMP** | The mcumgr management protocol the bootloader speaks (CBOR over framed serial), used to upload images (`image upload`, slot id 2 for the keyboard, 4 for the module bundle) and to reset (`os reset`). | <span class="tag static">STATIC</span> <span class="tag measured">MEASURED</span> | [Bootloader](firmware/bootloader.md) |
| **`.sfb`** | An encrypted module firmware file (`Touch_UserApp.sfb`, `Track_`, `Tune_`, `Float_`, `Query_`, each with a HASH file) inside `FlashMemory.bin`, staged in the left half's flash for the module to update from. | <span class="tag static">STATIC</span>; agrees with naya-create-kb | [Module firmware](firmware/modules.md) |
| **Speedlink** (vendor term) | The vendor's name for the wireless dongle (model NAYA-100-1, FCC ID `2BQ4V0825DG`). | <span class="tag doc">DOC</span> (manual) | [Speedlink dongle](hardware/dongle.md) |
| **SPIFLASH_TEST** (`fa/1001`) | The read-only SPI-flash self-test; per partition a state and five return codes. naya-create-kb calls `fa/1001` "device info". | <span class="tag static">STATIC</span> <span class="tag measured">MEASURED</span> (2026-09-10) | [Python recipes](tools/recipes-python.md) |
| **Split link** | The Bluetooth connection between the two halves (7.5 ms interval, 4 s supervision timeout on 3.41.0). | <span class="tag measured">MEASURED</span> (owner's board, 3.41.0, `be/100c`) | [Split link](connectivity/split-link.md) |
| **Status `16`** | The reply status meaning "nothing stored for this read" (a header-only frame; `18` on a continuation). naya-create-kb's `16 00` after a factory format is this status followed by the index `00`. | <span class="tag measured">MEASURED</span> (donor board, 3.28.7, 2026-09-19) | [Transport](protocol/transport.md) |
| **Subcommand** | Frame bytes 6-7, big-endian (`10 04` for `0x1004`). | <span class="tag static">STATIC</span> | [Transport](protocol/transport.md) |
| **Tapping term** | The hold-tap time in ms, stored inside every hold-tap record (both banks); NayaFlow writes its global value into each record; there is no device-wide term. | <span class="tag measured">MEASURED</span> (owner's board, 3.41.0, 2026-09-17) | [Settings and timing](protocol/settings.md) |
| **Trailer** (swap trailer) | The last bytes of a stock resource (`image_ok = 01` and the MCUboot magic), which make the bootloader swap the new image in permanently as soon as the upload ends. | <span class="tag static">STATIC</span> <span class="tag measured">MEASURED</span> (flashes of 2026-09-20) | [Firmware images](firmware/images.md) |
| **Two-word record** | A record whose parameter is two u32 values, command first (for example Bluetooth, LED keys, mouse buttons, module motion). | <span class="tag measured">MEASURED</span> <span class="tag static">STATIC</span> | [Disassembly](software/disassembly.md) |
| **Version gate** | A minimum keyboard firmware NayaCore requires for an operation or a command (for example 3.30.0 for REMAP commands, 3.36.0 for the activity timeouts). | <span class="tag static">STATIC</span> | [Disassembly](software/disassembly.md#version-gates) |
| **XOR checksum** | The XOR of subcommand high through the last payload byte (not the size byte). | <span class="tag static">STATIC</span> (NayaCore's broker frames) | [Python recipes](tools/recipes-python.md) |

## Terms other sites use

naya-create-kb coined several terms; here is what each one means on this site.

| Their term | Their meaning | Our reading | Evidence |
|---|---|---|---|
| **Dark saga** | Its 2026-09-17 incident in which a board's key LEDs went dark while modules stayed lit, which it traced to zero-filled ED settings. | An incident on its board; the mechanism (a short ED payload is zero-filled, and `ed/1013` 0 keeps keys dark) we measured ourselves. | <span class="tag reported">REPORTED</span>[^kb-glossary]; mechanism <span class="tag measured">MEASURED</span> |
| **Dead control** | A stock UI control with no wire path. | Of its examples, the scan-mode toggle, the LED-max slider and per-layer animations do reach the keyboard; macros are the one truly host-only feature. | <span class="tag measured">MEASURED</span> <span class="tag static">STATIC</span> ([NayaFlow and NayaCore](software/nayaflow.md)) |
| **Dirty flag** | The "tail triplet `4b 02 00`". | The Touch-right bay record (position `0x4b`) pointing at module-config slot 2, not a flag; it tracks the module assignment. | <span class="tag measured">MEASURED</span> (owner's board, 3.41.0, 2026-09-03) |
| **Merge host** | The left half. | The central (see Central / peripheral). | <span class="tag measured">MEASURED</span> |
| **MODMASK** | The top byte of a key-press parameter. | The parameter is `[usage lo][usage hi][page][modifier bits]`, a little-endian u32 `(mods << 24) + (page << 16) + usage`, so the top byte is the HID modifier bits. | <span class="tag static">STATIC</span> <span class="tag measured">MEASURED</span> |
| **NVS** | Settings the keyboard keeps across reboots (scan mode, LED layer override, maximum brightness), stored in LittleFS. | NayaCore has a status name "NVS" and verifies `scanmode_pwm` and `led_layer_override`; `ed/1013` survives reboots. That these live in a LittleFS partition is its reading, which needs a flash dump to check. | <span class="tag static">STATIC</span> <span class="tag measured">MEASURED</span> (2026-09-13); LittleFS <span class="tag reported">REPORTED</span>[^kb-glossary] |
| **Proxy** | The left port answering for the right half when addressed as `dst 0x51`. | Relaying is partial: the firmware-version read reaches the right half this way (on 2026-09-20 the left port read the right half's 3.35.4 while the right half's own port returned empty payloads), but Bluetooth identity reads sent to `0x51` on the left port answer for the left half, and the left half cannot be reached through the right port. The right half has no REMAP stores to answer from. Which sender byte a relayed reply carries is <span class="tag open">OPEN</span> ([details](open-questions.md#oq-c12)); its pages give two readings. | <span class="tag measured">MEASURED</span> (create-legacy-firmware[^nh-hw]) |
| **Shadow slot** | Position `KK+0x52`, the "mini/full" shadow record. | The second bank (see Second bank). | <span class="tag measured">MEASURED</span> |
| **Slot-id** | The second byte of an ED ack, read as a per-command constant rather than an echo of the value. | The reply's checksum: an empty ack's XOR is `10` ^ C1, which gives exactly its values (`1013` -> `03`, `1010` -> `00`, `1003` -> `13`, `1012` -> `02`, `1014` -> `04`, `1050` -> `40`, `1008` -> `18`, `1011` -> `01`). | <span class="tag inferred">INFERRED</span> (arithmetic) <span class="tag measured">MEASURED</span> (acks); see [Command map](protocol/commands.md) |
| **T-record** | A keymap record. | Record (see above). | <span class="tag measured">MEASURED</span> |
| **True cold boot** | USB unplugged, modules undocked, both switches off, then on; which it calls the only real reset besides `ee/10ce`. | It resets, but it is not the only one: switching a half OFF while it is on USB shuts it off, and switching it back ON works as a reset (the manual says the Create "will respect the ON/OFF state even while connected over USB"). Every power-on passes through the bootloader, and powering one half reboots the other when they re-link, so a one-half power cycle reboots both. | <span class="tag measured">MEASURED</span> (owner's board, 2026-09-22 and 2026-09-23) <span class="tag doc">DOC</span> (manual v1.1.x) |
| **Wedge** | The device state machine stuck by off-protocol input (stale commit replay, oversized frame, parked recovery). | The protocol handler stuck until replug or power cycle. Measured causes: any three-frame write on 3.28.7; oversized single LED-map frames (reported by a nayactl pull request #6 contributor on 3.41.0). A half parked in its bootloader is not wedged (an SMP reset brings it back). `fe/100a` is SET ACTIVITY TIMEOUTS, not a "commit", and identical replays did not wedge 3.41.0 in our captures; its replay wedge is its own observation. | <span class="tag measured">MEASURED</span> (donor board, 2026-09-19) <span class="tag reported">REPORTED</span>[^nx-pr6][^kb-glossary] |
| **Write-only map** | A static map in NayaCore with code that fills it and no code that reads it (its `+0x70`). | Confirmed and named: `naya_zmk::FLOW_AT_TO_ZMK`, and also `MOUSE_CODE_TO_PARAM_PAIR` (its `+0xb0`), are filled at start-up and never read. | <span class="tag static">STATIC</span> ([Disassembly](software/disassembly.md)) |
